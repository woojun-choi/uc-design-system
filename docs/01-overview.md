# 01. 개요

## 한 줄 요약
유명한 디자인 시스템 문서를 읽고 뽑아낸 원칙으로, 내 사이드 프로젝트(웹 + iOS)가 같이 쓰고 AI 코딩도 따르는 작은 개인 디자인 시스템.

## 왜 만드나
- **시작 비용 반복:** 사이드 프로젝트가 10개 넘게 있는데, 매번 색·글꼴·버튼을 새로 정하면 시작이 느리고 톤이 제각각이 된다.
- **AI 기본값 디자인:** Claude Code·Cursor로 UI를 만들면 "그럴듯하지만 평범한" 화면이 나오고, 화면마다 스타일이 조금씩 어긋난다. AI가 읽고 따를 규칙이 필요하다.
- **좋은 교재는 많은데 정리가 없음:** Material, Apple HIG, Carbon, 토스 TDS, 당근 SEED 같은 공개 문서는 최고의 교재지만, 무엇을 가져올지는 직접 골라야 한다. → [research/](../research/README.md)

## 출발점이 된 두 레퍼런스
1. **shadcn/ui 기반 커스텀 시스템** — shadcn/ui를 그대로 쓰지 않고, 검증된 UI/UX 패턴을 얹어 내 입맛대로 재정의. 컴포넌트를 npm 패키지로 받지 않고 **코드를 소유**하는 방식이라 개인 시스템에 맞다.
2. **Vercel Geist의 `DESIGN.md`** — 색·글꼴·버튼 규격·간격 규칙을 AI가 읽기 쉬운 텍스트로 정리한 문서. 디자인 시스템의 독자가 사람 → AI로 넓어지는 흐름.

**결론:** shadcn/ui 기반 토큰 중심 컴포넌트 + 사람과 AI가 모두 읽는 문서, 두 축으로 만든다.

## 네 갈래를 하나의 흐름으로
| 순서 | 갈래 | 결과물 | 상태 |
|---|---|---|---|
| 1 | 읽기 | 디자인 시스템 11개 읽기 노트, 원칙 12개 | ✅ 완료 ([research/](../research/README.md)) |
| 2 | 시작 도구 | 좋아하는 사이트 URL의 CSS에서 색·글꼴·간격을 뽑아 테마 초안으로 | 나중에 |
| 3 | 만들기 | 토큰 + 컴포넌트 + 테마 | ▶ 지금 |
| 4 | AI 연동 | DESIGN.md + AGENTS.md + 스킬 + lint | 만들기와 병행 |

## 쓰는 곳
1. **문서 사이트 / Storybook** — 처음엔 다른 프로젝트에 붙이지 않고 여기서 완성
2. **사진 포트폴리오 웹사이트** — 첫 실제 적용. 포트폴리오용 컴포넌트(갤러리 등)는 이때 추가
3. 이후 사이드 프로젝트 — SVG 아이콘 웹, 발표자료 앱, 감시 뽀모도로(iOS, 토큰만) 등

## 범위 밖
- 팀 협업·권한·버전 승인 같은 기업용 기능
- 50개 넘는 컴포넌트 라이브러리 (필요한 건 shadcn/ui에서 가져오면 충분)
- 공개·수익화 (개인용으로 확정)

## 성공 기준
- 새 사이드 프로젝트의 초기 UI 셋업이 하루 안에 끝난다
- AI로 만든 화면에 하드코딩된 색·간격이 거의 없다
- 무드가 다른 프로젝트 2개 이상에 테마만 바꿔 적용된다
